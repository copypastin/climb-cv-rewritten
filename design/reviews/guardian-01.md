# `plugin-api-guardian` review 01 — step-6 design surfaces

Date: 2026-08-07. Reviewer: `plugin-api-guardian`. Subject: `design/{plugin-api,payloads,loader,broker,isolation,config-contract}.md` as delivered by `framework-core`.

Settled and not relitigated: Decision #9 (locked), #12 (accepted), #17 (accepted), no sandbox in v1, no config schema validation in v1.

Verdict: strong body of work. Five items the project would get stuck with; eighteen recoverable-but-painful; rulings on the five open naming questions and on Decisions #14/#15.

---

## BLOCKING

### B1. `latest()` returns no `Meta`, cancelling the premise Decision #12 was accepted on

`self.latest(topic)` returns the newest payload and discards the envelope, so a shared-topic subscriber cannot tell which publisher a value came from — the exact capability `broker.md` §3.1 cites as making `holds.boxes` safe to share.

**Failure.** User installs `yolo_holds` + `route_map` (the pair in the design's own `climbcv topics` sample output and its motivating example). `exo_live` calls `self.latest("holds.boxes")` once per frame. `route_map` publishes its static annotation; `yolo_holds` publishes every 4th frame. From the first YOLO detection onward `latest()` never returns the route map again — annotated route invisible, no error, no log. Reverse the cadence and the overlay flickers between sets. §3.1's stated mitigations (colour by source, filter to one source, draw everything) are all unreachable through the only accessor the API offers.

**v2 cost.** Changing `latest()`'s return type breaks every plugin using it, and it is the accessor the flagship `ExoLive` example teaches — an example `plugin-api.md` §6 hands to `docs-and-testing` as "the *whole* of how to write a plugin."

**Recommendation.** Keep `latest(topic) -> payload | None` for the single-publisher case; add `latest_by_source(topic) -> Mapping[str, payload]` (empty mapping, never `None`) now. Rewrite `ExoLive` §2.1 to use it for `holds.boxes`. Add a startup WARNING when a plugin subscribes to a topic that resolved to more than one publisher. Also specify two undefined behaviours: `latest()` on an undeclared topic should raise `UndeclaredTopicError` symmetrically with `publish()`; and `latest()` must state whether it reflects messages drained this turn whose handlers have not run (it should — otherwise `on_frame` reading `latest("pose.smoothed")` is needlessly a frame stale, which is what §4.3 exists to fix).

### B2. `PoseFrame` cannot express `mirrored`, so left/right body semantics are unrecoverable

`Frame.mirrored` is documented as mandatory reading ("a subscriber computing 'which hand' MUST read it"), but `PoseFrame` has no `mirrored` field, and `world`'s axis definition is "+x subject's image-right" — mirror-dependent. Under full isolation `pose.smoothed` arrives on a different topic from `frame`, and a pose subscriber need not subscribe to `frame` at all.

**Failure.** `hand_sequence` subscribes only to `pose.smoothed` and logs which hand reached each hold — no reason to subscribe to `frame`, it needs no pixels. It cannot see `mirrored` and reports left/right swapped whenever capture mirrors, which is the default in current code (`cv2.flip(frame, 1)`). Same downstream of `core.persist_npy`: the saved `.npy` carries no mirror flag, so every offline analysis of a saved session is a coin flip. Nothing raises.

**v2 cost.** By the design's own change-rule table, adding a required field is a **major** bump and a `pose/1`→`pose/2` increment — invalidating every third-party pose publisher and subscriber written against v1.

**Recommendation.** Add `mirrored: bool` to `PoseFrame`, copied from the originating `Frame` exactly as `t_capture_ns` already is. Note the inconsistency this fixes: the design correctly decided `topology` must travel with the payload rather than be looked up, then left the other semantics-determining flag to be looked up on a different topic. If declined, `world`'s axes must be restated in mirror-independent anatomical terms and `PoseFrame` must say so — but the field is one line and strictly better.

### B3. Payload arrays are mutable, and whether a subscriber may write to them is undecided

`frozen=True` freezes references, not the numpy buffers that are the entire content. §2.2 states the goal — "a mutable payload invites authors to build code that only works when they happen to be the only subscriber" — and the mechanism does not deliver it. No docstring says whether `frame.pixels` or `pose.world` may be written.

**Failure, two directions.** (a) `stabilize` subscribes `frame` and does `frame.pixels[:] = cv2.warpAffine(...)` expecting downstream subscribers to see it. No effect — each subscriber holds its own unpickled copy — so the plugin silently does nothing and the author files a framework bug. (b) A plugin does `pose.world[:, 1] *= -1` in one handler and reads `latest("pose.smoothed")` in another; the cached payload is now corrupt in-process and every later read is wrong.

Related and separately unspecified: `Frame.as_bgr()`/`as_rgb()` have no documented return contract. Implemented as `pixels[..., ::-1]` they return a negative-stride, non-contiguous view — and §2.1's YOLO example passes exactly that into `model.predict()` without a copy while the `ExoLive` example copies. The two examples imply opposite things about contiguity and mutation safety.

**v2 cost.** The design's own row: "tighten a validation rule that previously passed → treated as breaking." Setting `writeable = False` in v1.x breaks every plugin that mutates in place and works today.

**Recommendation.** Set `arr.flags.writeable = False` on every array in `__post_init__`; state in each docstring that arrays are read-only and consumers must `.copy()`. Turns the `stabilize` no-op into `ValueError: assignment destination is read-only` and costs nothing per message. Specify `as_rgb()`/`as_bgr()` as "always returns a new C-contiguous `uint8` array, safe to mutate", then drop the `.copy()` from the `ExoLive` example so the examples agree.

### B4. `requires_topology` defaults to "any", so the highest-value check doesn't fire for the plugins most likely to need it

§4 calls the wiring-time topology check the highest-value item in the document, then makes the subscriber's half opt-in: omitted means "any", no check runs. The failure mode §1 defines is "nobody read the doc", and `requires_topology` is a doc-read-dependent declaration.

**Failure.** An author copies §2.1's `ExoLive` (shows no manifest) and `templates/detector/`'s manifest (a detector, so no `requires_topology` line to notice). They index joint 11 for a shoulder. User swaps in `fast_pose` providing `coco.17`; index 11 is a hip under COCO; the overlay draws a wrong skeleton every frame with no error — precisely the scenario §4's error message exists to prevent, never printed. Indices above 16 would raise, so low-index joints (face, shoulders, hips — the ones overlays actually draw) are the silent ones.

**v2 cost.** Reversing the default later is a breaking manifest change for every plugin that omitted the field, so in practice the unsafe default persists and the mechanism protects only careful authors, who were never the risk.

**Recommendation.** Make the declaration mandatory for any plugin subscribing to `pose.*`, with explicit opt-out `requires_topology = "any"`. Omission becomes a manifest error listing the two choices, teaching the concept without requiring the guide. This is the identical trick already used, with identical reasoning, for `subscribes.required = true` — "a mistyped topic name that silently delivers nothing forever is one of the worst authoring experiences pub/sub has." The safe direction was chosen there and the unsafe one here; make them consistent.

### B5. A plugin cannot carry an author-defined payload, and the class-by-reference path silently unpickles into the wrong class

`loader.md` §3 advertises author-invented topics (`acme.grip_force`) but constrains `payload` to a `climbcv.contracts` type, so the six framework types are the entire expressible payload vocabulary — a framework-owned enumeration in exactly the shape Decision #12 rejected for exclusivity. The obvious workaround is mechanically broken: `isolation.md` §3.1 sets `sys.path[0]` to the plugin's own directory and `entry` is conventionally `"plugin:Class"`, so **every** plugin's classes pickle under the qualified name `plugin.<Class>`. A subscriber unpickling `plugin.RouteGraph` resolves it against *its own* `plugin.py`.

**Failure.** `route_map` publishes a route graph with hold-to-hold edges and grades. No contract type carries it; `HoldBoxes.labels` is the only string field, so the author smuggles JSON through it. Define their own dataclass instead and the subscriber raises `AttributeError: Can't get attribute 'RouteGraph' on module 'plugin'` — or, if the subscriber defines a same-named class, unpickles into the **wrong class** with no error.

Separately: nothing type-checks a payload against its topic descriptor, so `self.publish("holds.boxes", PoseFrame(...))` enqueues fine and the `AttributeError` surfaces in the *subscriber's* handler, where §6.2's ladder logs "handler `on_holds` has raised 148 times" and attributes the bug to the innocent plugin.

**Recommendation.** (a) Ship a generic `Record(kind: str, data: dict)` in `climbcv.contracts`, validated to contain only TOML/JSON primitives, so custom payloads cross as data with no plugin class in the pickle stream. (b) Make `publish()` assert `isinstance(payload, descriptor.payload)` and raise `PayloadTypeError` naming topic, expected and actual type — one `isinstance` per publish, in the publisher's process where the bug is. Also state as a rule: nothing but `climbcv.contracts` types crosses the data plane, nothing but strings crosses the control plane — `isolation.md` §4.2 says "traceback already sent on the control queue", and if that is an exception object rather than `format_exc()`, a plugin-defined exception class breaks the crash-reporting path the same way.

## SHOULD-FIX

**S6. Decision #15's justification and the `__init__` error text are factually wrong.** Both `plugin-api.md` §3.1 and `isolation.md` §3.2 justify reserving `__init__` as avoiding "an opaque pickling error at spawn time", and the message tells the author things created there "cannot come along". But `isolation.md` §3.1 step 7 instantiates the plugin **in the child**, after spawn — no plugin instance is ever pickled, so the stated failure cannot occur. The reservation is still right for a different reason: the framework binds `config`, `log`, `publish`, `latest` at step 7, so inside `__init__` none exist, and an author's first instinct there is `self.config.get(...)`. Fix the message to say the true thing, and fix the Decision Log entry before it locks — the pickle-safety property is real but comes from `spawn` plus child-side construction, not from the reservation. Discoverability: nothing an author reads *in code* says `__init__` is reserved — add a commented line to both templates and the §2 class sketch. On violation, the current path spends two spawn attempts and, for a critical publisher, escalates to whole-app shutdown — three stacked messages with the useful one buried. Deterministic contract violations (`__init__` defined, not a `Plugin` subclass, `@subscribe` with no manifest entry) should be a non-retryable `PluginContractError`: quarantine on first occurrence, one message, no app-shutdown escalation.

**S7. Startup fatals caused by third-party declarations leave the user no local recourse, and messages point at a file that may not exist.** (a) Descriptor contradiction: two authors legitimately disagree on `exclusivity`/`kind` for a community topic name, with no config key to override either; the message says "usually the publisher is right", meaningless when both are publishers. (b) `config["topics"][name]["publisher"]` naming a skipped plugin → fatal even when skipped benignly; a team sharing one `climbcv.toml` that pins a mac-only smoother gives every Linux teammate a hard startup failure — contradicting the reasoning applied to `platforms` ("a Linux user running a config that mentions a mac-only plugin has done nothing wrong"). (c) Starved required subscription → fatal, only fix is asking the author to edit their manifest. Add `[topics.<name>] exclusivity=/kind=` local overrides, fall back to remaining candidates with a WARNING when a named publisher was benignly skipped, and allow a user-side subscription-optional override. Independently: `config-contract.md` §1 provides `source` so errors can say where a value came from, and **no error message in any design file uses it** — when `source == "<defaults: no config file found>"`, every paste-ready TOML snippet must say which file to create and where.

**S8. `teardown()` is the only flush hook, budget 1 s, terminate on overrun — so the first-party persistence plugin can lose the user's session.** `isolation.md` §7 sets `teardown_timeout_s = 1.0` and tells authors teardown "is for closing files, not for finishing work". But `core.persist_npy` exists to write the run's landmarks at the end, and a third-party MP4 writer must finalize a container, routinely seconds. Hour-long session, slow external drive, teardown exceeds 1 s, process terminated mid-write, hour gone with a WARNING. This is the dogfood test failing in the sense the brief cares about — a first-party plugin needing something the public API can't express. Make the budget declarable per plugin (`teardown_timeout_s`, default 1.0, documented cap) **and** have `core.persist_npy` append incrementally so its teardown is a `close()`.

**S9. A STREAM message published once can be evicted before its subscriber ever reads.** §5.1.1 establishes that a `frame` burst can evict another topic's pending message; §5.4 says a late subscriber "has missed everything" — but the consequence for a once-only publisher is unstated and permanent, not the "≤500 ms wait" §3.5 implies. `route_map` publishes once in `setup()`; `exo_live`'s `setup()` takes ~3 s building a window and figure; its stream depth is `max(4, 2×4)=8`; by the time it reads, 90 frames have arrived and the single `holds.boxes` message is gone. `latest()` returns `None` for the whole session. State plainly in §5.4 and the guide that a STREAM message published once may never be seen and static data must be republished on an `@every` tick. The structural fix is a `retain`/`state` kind — genuinely new machinery; documentation suffices for v1 if prominent.

**S10. `stream_depth`'s documented default disables the starvation mitigation if a user writes it down.** §8 and `config-contract.md` §2 list `stream_depth` (4); `broker.md` §5.1.1 computes `max(4, 2 × stream subscriptions)` and lets config override. A user copying the documented default into `climbcv.toml` pins depth 4 and silently reintroduces the frame-evicts-pose starvation §5.1.1 prevents. Document the default as `auto` (or `0` = computed), never `4`, and print resolved per-plugin depth in `climbcv topics -v`.

**S11. `topology` is spot-checked once per run in the publisher; the subscriber-side per-message check is free.** §4 asserts only that the *first* `PoseFrame` matches `provides_topology`. Existing code already has a MediaPipe GPU→CPU delegate fallback, so multi-path pose publishers are real: `multi_pose` publishes `mediapipe.pose.33`, the GPU delegate dies at t=60 s, it falls back to a bundled 17-point model, and every payload after is internally consistent while contradicting the wiring-time contract. Subscribers indexing 0–16 read different joints silently for the rest of the run. Compare `payload.topology` against the wired expectation on **every** delivery in the subscriber; fatal for that subscriber with an attributable message. One string comparison — cheaper than the `np.isfinite(world).all()` already run per construction.

**S12. `plugin-api.md` §4.2's `Meta.seq` claim is false on shared topics.** "A decrease in `seq` means publisher restarted, not reordering" holds per `(publisher, topic)`, not per topic — and `holds.boxes` is shared by an accepted decision. Two detectors at seq 400 and seq 3 make an overlay's drop-detection fire on alternating messages. Reword to "track `seq` keyed by `meta.source`". One sentence, but as written it will be copied into the guide and then into plugins.

**S13. `Scalar`'s unit lives in prose and is excluded from the descriptor-merge check.** `Scalar` says "unit is fixed by the topic; consult the topic descriptor", and the descriptor's unit information is a free-form `doc` string. §4.2 merges on `kind`, `exclusivity`, `schema` only. Two plugins declaring `acme.grip_force` in newtons and kgf agree on every checked field, wire successfully, and disagree by 9.8× forever. Make `unit` a required manifest key when `payload = "scalar"` and add it to the merge equality check — the existing "descriptor contradiction" error then produces the message for free. One field, extending the best mechanism into the space where most topics will live.

**S14. `version` is free-form now and unparseable later.** §3.1 makes it informational, recommending semver in the guide. The ecosystem will contain `"v1.2 beta"` and `"2024-06-01"`, and any future registry or update check cannot compare them. Validate `MAJOR.MINOR.PATCH[-prerelease]` at manifest load — costs nothing today, preserves the option; tightening later is breaking by the project's own rule.

**S15. Two cheap loader items.** (a) The `id` grammar `[a-z][a-z0-9_]{1,63}` forbids dots, but built-in ids are `core.capture` and `config-contract.md` §3.3 says plugin-id keys "may contain dots". State the grammar as permitting dots with `core.`/`climbcv.` reserved, or say built-in ids sit outside the third-party grammar. (b) A typo in `entry` is discovered in the child at import, costing two spawns and reading as a crash. Module-file existence is a pure filename check at discovery — the same trick already used for stdlib shadowing — so make it a manifest error at startup listing the `.py` files actually present.

**S16. Vendoring is the recommended dependency answer with no way to declare architecture.** §6 tells authors to vendor into `plugins/<id>/vendor/`, and `platforms` expresses only `sys.platform`. A plugin vendoring an x86_64 wheel runs on Apple Silicon and fails with `ImportError: incompatible architecture` — a cryptic failure produced by the framework's own recommended mitigation. Say in §6 and the guide that `vendor/` is architecture-, ABI- and Python-version-specific; better, let `platforms` carry arch tags. The §6 message also prints the manifest's unvalidated `requires` list, so when empty it reads "lists these requirements: (none)" and looks like a framework bug — and it should print the **actual interpreter path plus a ready `-m pip install` command**, since "install them into the environment running climb-cv" is the entire difficulty when the user plausibly has three Pythons.

**S17. No graceful "not applicable here" for preconditions that aren't `sys.platform` — a first-party/third-party asymmetry.** The mac lid sensor gets a declarative skip via `platforms = ["darwin"]`, INFO, no drama. A third-party plugin depending on a GPU, a camera, a file, or an env var must raise in `setup()`, producing two spawn attempts and `Plugin 'depth_holds' has been disabled: it crashed 2 times` — reading as broken rather than "you don't have that hardware". Whether `finish()` may be called from `setup()` is also unspecified. Cheapest fix reusing existing surface: define `finish()` as legal in `setup()`, meaning "not applicable on this machine, skip me" → INFO, no retry, no quarantine, participating in absent-topic resolution like a platform skip.

**S18. A blocking source has no author-visible way to notice shutdown.** §3.3 blesses a blocking `@every(0)` handler as the way to write a source, and checks the shutdown Event only between calls. An IP-camera plugin whose `read()` stalls ten seconds is terminated after `grace_s = 2.0`, `teardown()` never runs, device handle leaks. There is no `self.stopping`. A read-only boolean property is not a concurrency primitive — same category as `self.config` — so §3.6's blanket "no concurrency helpers" is over-broad here. Add it in v1, for the reason in S22.

**S19. The embedding API is a public surface with no design section, and is the one participant exempt from every rule the plugin API enforces.** `broker.md` §7 shows `<host>` as a subscriber of `pose.smoothed` and both publisher and subscriber of `app.shutdown`; `ClimbCV.subscribe(...)` appears in the §1.1 diagram. Nothing specifies it. Does a host subscription count as `required` for §4.2 step 5 and §5.3's shutdown escalation — when `core.pose_mediapipe` quarantines and the only pose consumer is an embedder's callback, does the app exit? Can the host subscribe to an absent topic? Is there a `ClimbCV.publish()`? Most consequentially: `<host>` has no manifest, so it cannot declare `requires_topology` — the highest-value check does not protect the embedding API at all, and swapping in a `coco.17` pose plugin silently changes the meaning of every index in every embedder's callback. Given `start(blocking=False)` with `on_landmarks` is an existing documented capability, this needs its own section before lock. Verify `spawn` from a Jupyter notebook while writing it — the most likely embedding environment, and `__main__` re-import is the classic failure; it should work (only package-level `child_main` plus dataclasses and dicts are pickled, host callbacks never cross a boundary) but prove it.

**S20. Built-ins carry "synthetic manifests", quietly weakening the dogfood claim.** §5 registers `core.*` from a built-in provider list with manifests constructed in code. So the four built-ins are not readable `climbcv-plugin.toml` reference examples, and the manifest parsing/validation path is not exercised by the first-party conversions — manifest bugs will be found by third parties, not by dogfooding. Ship built-ins as real directories with real manifests parsed by the same code. This is the one place full isolation does create asymmetry — in the loader, not the runtime.

**S21. `Status.state` is a free-form string whose vocabulary is already inconsistent across two documents.** The docstring lists ready/crashed/restarted/quarantined/stalled; `isolation.md`'s messages say "has been disabled" and "is shutting down". A dashboard matching `state == "quarantined"` matches an unenumerated, unversioned, already-divergent vocabulary. Put the literal set in `contracts.py`, validate in `__post_init__`, give it a change rule. Also `Status.plugin_id` is a payload field and therefore forgeable, contradicting §2.3's own principle that identity must be framework-injected — a plugin can publish `Status(plugin_id="core.pose_mediapipe", state="crashed")`. Not a security issue under Decision #6, but the type should say `plugin_id` names a *subject* while only `Meta.source` names the sender.

**S22. No reserved namespace on `self`, so adding a member in a minor version is not actually additive.** The base class occupies seven names and authors assign freely to `self` in `setup()`. §4's compatibility model is "additive minors, breaking majors", but `self.latest = deque(maxlen=10)` shadows a framework method and produces `TypeError: 'deque' object is not callable` from a handler — and conversely any member added in v1.x can collide with an attribute an existing plugin uses. Document the seven names plus any future `cv_`-prefixed name as reserved, **and** have the child runtime verify after `setup()` that none was rebound, raising attributably. A handful of lines, converting a cryptic runtime `TypeError` into a clear load-time message. Also why S18's `self.stopping` should land in v1 rather than v1.1.

**S23. `climbcv validate` cannot catch the one divergence class with no startup detection.** §7 makes an undeclared `publish()` raise at the call — but a conditional publish (`acme.rare_event`, fired only on a rare condition) ships, works for months, then raises inside a handler where §6.2's ladder logs and suppresses it rather than failing loudly. §7 claims `validate` "keeps the two honest"; for publishes it currently cannot, since importing reveals decorators but not conditional call sites. Have `validate` AST-scan for `self.publish("<literal>")` and diff against `[[publishes]]` — pure AST, no import, catches nearly all of it.

## NOTES

- `app.shutdown` shares the generic event queue's drop-newest-when-full policy. Depth 256 makes it unlikely, but the consequence is "the ESC key silently did nothing", the one path that must never fail. `Shutdown` is idempotent so drop-oldest is strictly better for it; at minimum log a dropped `app.shutdown` at ERROR and state the guarantee.
- `@every(n)` doesn't define whether the interval measures from handler start or return, nor whether missed ticks coalesce. Irrelevant at 0.5 Hz, load-bearing at `@every(0.033)`; "ticks queue up" would be an unbounded-backlog bug. One sentence: interval from return, missed ticks dropped never queued.
- `Frame.color = "gray"` carrying a replicated (H, W, 3) buffer triples serialization cost for grayscale sources on the exact path with the documented 640×480 ceiling. The one-code-path argument is defensible; the cost belongs in §5.3's table.
- `HoldBoxes` states its coordinate origin; `Frame.pixels` and `PoseFrame.image` do not. By §3's own review criterion, two of three coordinate-bearing types are incomplete. Two lines.
- `platforms` is restricted to `{darwin, linux, win32}` — a framework-owned enumeration of the kind Decision #12 rejected. On FreeBSD every plugin declaring `platforms` is skipped while every plugin omitting it runs. Accept any `sys.platform` string, warn on unrecognized.
- The stall warning will false-positive on the blocking `@every(0)` source §3.3 explicitly blesses — a 10 s network read warns twice. Word it so it doesn't read as a bug, and name `heartbeat_warn_s` in it.
- Name the `__main__`-guard detection mechanism in §2.4: `multiprocessing.parent_process() is not None` checked in `ClimbCV.run()` catches it on first re-entry, whereas a naive implementation notices only after processes have multiplied.
- Template plugin ids should be obviously placeholder (`my_detector`, not `detector`) — two authors who both copy `templates/detector/` without renaming produce a duplicate-id **fatal** for the user who installs both.

## Rulings on the five naming questions (`plugin-api.md` §6)

1. **`setup`/`teardown` — keep.** `start`/`stop` collides with `ClimbCV.start()`/`.stop()`, making every doc sentence ambiguous about app vs plugin. `on_setup`/`on_teardown` reads as a handler for an event named "setup", and no such topic exists. Caveat for the docstring: in pytest/unittest these run *per test*, so the carried intuition is "once per unit of work" — say "once, in this plugin's own process, before any handler runs."
2. **`latest()` — keep the name, fix the return.** `last()` is ambiguous between "most recent" and "previous"; `current()` implies always-present. The problem is B1, not the name.
3. **`@every(seconds)` — keep.** `@every(0)` composes to "as fast as possible" while `@tick(0)` reads as "never", and a source needs exactly that. Additional reason: `@tick(30)` invites an author to describe a device-bound rate as a timer rate, a lie the API shouldn't help them tell.
4. **`join=` — cut from v1.** Undefined on shared topics: with two detectors both publishing `frame_seq=100`, does the handler fire once or twice, with which source? Silently broken against `PoseFrame.frame_seq == -1`, the replay-source sentinel — and `broker.md` §8 *recommends* building `replay()` as a plugin publishing `pose.smoothed`, so two recommended features combine to a handler that never fires and a blank overlay with no error. And it breaks §3.3's invariant that "the handler signature is always `(self, payload, meta)`" by introducing a variadic form whose parameter order must silently match the decorator's topic order — swap them and the payloads swap with no error. Adding `join=` later is a keyword argument with a default, a clean additive minor, so this is the cheap direction to defer. The documented three-line `latest()` + `frame_seq` fallback is sufficient. If it stays, specify both the shared-topic multiplicity and the `-1` case.
5. **`finish()` — keep the name, fix the contract.** Per `isolation.md` §4.4, calling it can shut down the entire app when the plugin is the resolved publisher of a topic with required subscribers, while the API sketch documents it as `# "my work is done" -- orderly, not an error`, which reads local and modest. An author writing a batch plugin over a config-specified image list calls `finish()` when the list is exhausted and, if it publishes `frame`, has just ended the user's session unknowingly. State the escalation in the docstring, and add the missing log message for that path — §5.3 has an excellent causal message for quarantine-triggered shutdown; §4.4 has none for the `finish()`-triggered one and needs the same shape. Also settle whether `finish()` is legal in `setup()` (S17).

## On Decision #14 (full isolation)

**The argument holds and is the strongest available.** Options X and Z were rejected for observable asymmetry between built-ins and replacements; that reasoning is correct on the two axes named (latency, crash semantics) plus a third unnamed: with built-ins in-host the *diagnostic* surface forks too — a built-in's traceback lands in the host log with no `logs/<id>.log` and no `faulthandler` redirect, so "how do I debug this stage" has a different answer depending on who wrote it. For a public ecosystem a documentation fork is as costly as a behavioural one. Costs are stated honestly; benefits are real and mostly unclaimed elsewhere (macOS main-thread constraints satisfied by construction, narrower per-process imports, native crashes made attributable). Concur with T1: `transport` never appears in the authoring interface, so shared memory is a non-breaking upgrade whenever the ceiling is reached.

**It creates two asymmetries of its own,** both fixable inside the decision: S19 (the host is a data-plane participant with no manifest, no `api_version`, no declared subscriptions, no `requires_topology`, and no place in the resolution rules — visible as `<host>` in the CLI output and undefined everywhere else) and S20 (synthetic built-in manifests mean uniformity is real at runtime but not in the loader).

## On Decision #15 (`__init__` reserved, `setup()` in the child)

**Mechanism right, justification wrong — correct it before lock.** See S6. No plugin instance is ever pickled, because §3.1 constructs it in the child at step 7, so the cited "opaque pickling error at spawn time" cannot happen. The pickle-safety property is genuinely true but comes from `spawn` plus child-side instantiation and would hold even if `__init__` were permitted. The real reason is ordering: the framework binds `config`, `log`, `publish`, `latest` at step 7, so inside `__init__` none exist. Worth stating more confidently that the reservation is *narrow*: under `spawn`, module-level and class-body code also run in the child, so the usual "heavy work at import time" trap is already harmless and `__init__` really is the only hole.

**Discoverability: not yet, cheaply fixable.** The rule lives only in prose across two design files; nothing an author reads in code says it, and `def __init__(self): super().__init__(); …` is the most ingrained reflex in Python.

**On violation:** the right message, twice, buried — two spawn attempts, two copies, a quarantine summary, and for a critical publisher a §5.3 escalation to whole-app shutdown, for a deterministic one-line mistake. Hence the non-retryable `PluginContractError` in S6.

## What the guardian judges sound

Recorded so the revision pass doesn't churn on these.

- **The `topology` mechanism is the right shape** and does convert the worst silent-failure mode into a startup error naming both plugins and both topologies. Objections are to its default (B4) and once-per-run enforcement (S11), not the design. Putting `topology` on the payload rather than making it a lookup is correct, and §4.1's rejection of per-landmark name mapping is well-reasoned.
- **The versioning story is genuinely closed.** "One installation, one `climbcv.contracts`, so payload types cannot skew independently" justifies the coarse `api_version` mechanism rather than papering over it. Rejecting per-message version fields because climb-cv is one process tree, not a distributed system, is right and rarely made.
- **The change-rule table, especially "tighten a validation rule that previously passed → breaking."** That is the row people fudge, and writing it down before it is tested is the most valuable line in the document. Three blocking findings are things this rule will bind the project to — the rule working.
- **Fixing the box-coordinate convention while declaring `Frame.color`**, under the principle "fix the convention where conversion is free; declare it where conversion is expensive." Correctly applied, and it earns an unclaimed property: because boxes are normalized, a detector at 640×480 and an overlay at 320×240 are correct, and stay correct across mid-run resolution changes.
- **Decision #12's reversibility argument** is the right way to break a genuine tie, and the criterion beats the enumeration it replaces. B1 is that the accessor doesn't yet deliver on it, not that the decision is wrong.
- **`Meta.source` framework-injected and unforgeable** — the load-bearing idea in the whole payload design.
- **`required` defaulting to true, doing triple duty** (wiring validation, crash escalation, intentional completion), with shutdown escalation falling out of declarations rather than a hardcoded critical-plugin list. Genuinely ceiling-free and the cleanest thing in `isolation.md`.
- **The error messages as a body of work** — exclusive contention, starved subscription, unknown-topic-with-did-you-mean, both `api_version` directions, and a quarantine message that says what the user *loses* rather than only what failed. Complaints are about fatals with no local escape (S7), not the prose.
- **Diagnose-don't-intervene on hangs**, reasoned from the never-block invariant rather than squeamishness.
- **The teardown non-contract** — "may run while your inputs are still publishing and while your outputs are already gone" — exactly the right amount of promise. Refusing to invent ordering semantics is the harder and better choice.
- **Two implementation notes that will save someone a day**: `mp.Queue.full()` works on macOS where `qsize()` raises; stdlib `QueueHandler` is the right log transport (its `prepare()` formats the record and clears `exc_info`/`args`, so records are picklable by construction — precisely the hazard B5 raises for the crash-report path, and the reason to route tracebacks as strings).
- **The stdlib-shadowing filename check** — a pure filename comparison against `sys.stdlib_module_names`, no import, catching a baffling bug class for nearly nothing. That instinct is the one to reuse in S15(b) and S23.
